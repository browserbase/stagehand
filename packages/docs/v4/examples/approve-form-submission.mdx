## Goal and output

Fill the [httpbin test form](https://httpbin.org/forms/post) in a Browserbase cloud browser. Pause before the final `act()` that submits it. Answering `n` exits without submitting; answering `y` submits once and prints the destination URL. This is a local CLI approval example, not a persistent review service.

## Prerequisites and inputs

Add `BROWSERBASE_API_KEY` and `OPENAI_API_KEY` to `.env`. These folders use OpenAI as the example model provider; see [model configuration](/v4/configuration/models) to use another provider with Stagehand. TypeScript needs Node.js 22.18+ and pnpm, Python needs Python 3.11+ and uv, and Go needs Go 1.26+. Change the test name, email, size, and comments at the call site when adapting the job.

## How the job works

1. Launch Browserbase and create Stagehand. Keep both alive until the answer is received.
2. Fill the form with `act()` and `%variable%` placeholders. Check each result's `success` field so a failed fill cannot proceed to approval.
3. Present a single submit action. TypeScript separates `fillForm` and `submitForm` tools; only `submitForm` has `needsApproval: true`. Python and Go read `y` or `n` from stdin before the submit call.
4. Submit at most once, print the result URL, and close both resources in `finally` or deferred cleanup.

The TypeScript submit tool asks for approval before its `execute` function runs:

```typescript
submitForm: tool({
  description: "Submit the filled test order form.",
  inputSchema: z.object({ summary: z.string() }),
  needsApproval: true,
  execute: async () => {
    const result = await stagehand.act(
      "Click the Submit order button",
      { page },
    );
    if (!result.data.success) {
      throw new Error(result.data.message);
    }

    return { submitted: true, url: await page.url() };
  },
}),
```

The CLI keeps the browser open while waiting for an answer. If you move approval to an asynchronous service, persist the pending approval ID, model messages, and Browserbase session ID so you can resume the same action.

## Expected result and failure checks

The filled page appears before `Submit this form? [y/N]`. `n` prints a rejection and never clicks Submit. `y` produces one submission and a URL. Missing keys fail before browser launch. A failed form action or submission exits with an error.
