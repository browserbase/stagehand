## Agent brief

Give this brief to your coding agent. It should connect the approval request to your existing UI, queue, or API instead of copying the sample CLI prompt into production.

```text
Add human approval before this AI SDK agent submits a form with Stagehand v4.

Requirements:
- Split form preparation and final submission into separate AI SDK tools.
- Mark only the submission tool needsApproval: true.
- Use Stagehand variables for user values instead of interpolating them into
  natural-language action prompts.
- Keep the same Stagehand browser alive between the first model call and the
  approval response so the filled form is not lost.
- Show the reviewer the pending tool name and validated input.
- On rejection, tell the model not to request the same action again.
- Close Stagehand and the browser in finally blocks.

For an asynchronous review flow, persist the model messages, approval ID, and
Browserbase session ID before returning control to the reviewer.

Verify that rejection never executes submit, approval executes it exactly once,
and an expired browser session produces a recoverable error.
```

**Goal:** Put consent immediately before a browser action that changes external state.

**Outcome:** The model can prepare the form autonomously, but the final click cannot run until a human approves its typed tool call.

## Stack

- Node.js 24 or newer
- `@browserbasehq/stagehand`
- Vercel AI SDK and `@ai-sdk/openai`
- Zod 4
- Browserbase

## Set up the project

```bash
mkdir stagehand-approved-form && cd stagehand-approved-form
pnpm init -y
pnpm add @browserbasehq/stagehand ai @ai-sdk/openai zod@4.4.3
```

Set `BROWSERBASE_API_KEY` and `OPENAI_API_KEY`, then create `index.ts`:

```typescript
import { openai } from "@ai-sdk/openai";
import { browserbase, Stagehand } from "@browserbasehq/stagehand";
import {
  generateText,
  stepCountIs,
  tool,
  type ModelMessage,
  type ToolApprovalResponse,
} from "ai";
import { createInterface } from "node:readline/promises";
import { stdin, stdout } from "node:process";
import { z } from "zod/v4";

const browserbaseApiKey = process.env.BROWSERBASE_API_KEY;
if (!browserbaseApiKey) throw new Error("BROWSERBASE_API_KEY is required");

const browser = await browserbase.launch({
  apiKey: browserbaseApiKey,
});

try {
  const stagehand = await Stagehand.create({ browser });
  try {
    const page = await browser.context.activePage();
    if (!page) throw new Error("No active page");
    await page.goto("https://httpbin.org/forms/post");

    const tools = {
      fillForm: tool({
        description: "Fill the test order form without submitting it.",
        inputSchema: z.object({
          customer: z.string(),
          email: z.string().email(),
          size: z.enum(["small", "medium", "large"]),
          comments: z.string(),
        }),
        execute: async ({ customer, email, size, comments }) => {
          await stagehand.act("Type %customer% into the customer name field", {
            page,
            variables: { customer },
          });
          await stagehand.act("Type %email% into the email field", {
            page,
            variables: { email },
          });
          await stagehand.act(`Select the ${size} size`, { page });
          await stagehand.act("Type %comments% into the comments field", {
            page,
            variables: { comments },
          });
          return { filled: true, customer, email, size, comments };
        },
      }),
      submitForm: tool({
        description: "Submit the filled test order form.",
        inputSchema: z.object({
          summary: z.string().describe("A short summary shown to the approver"),
        }),
        needsApproval: true,
        execute: async () => {
          await stagehand.act("Click the Submit order button", { page });
          await page.waitForLoadState("domcontentloaded");
          return { submitted: true, url: await page.url() };
        },
      }),
    };

    const messages: ModelMessage[] = [
      {
        role: "user",
        content:
          "Fill the form for Ada Lovelace, ada@example.com, medium size, with the comment 'Leave at reception', then submit it.",
      },
    ];

    let result = await generateText({
      model: openai(process.env.OPENAI_MODEL ?? "gpt-5.4"),
      instructions: "Use fillForm before submitForm. If submission is denied, do not retry it.",
      messages,
      tools,
      stopWhen: stepCountIs(8),
    });
    messages.push(...result.response.messages);

    const pending = result.content.filter(
      (part) => part.type === "tool-approval-request",
    );
    if (pending.length === 0) throw new Error("The model did not request submission approval");

    for (const request of pending) {
      console.log("Pending browser action:", request.toolCall.input);
    }

    const prompt = createInterface({ input: stdin, output: stdout });
    const answer = await prompt.question("Submit this form? [y/N] ");
    prompt.close();
    const approved = answer.trim().toLowerCase() === "y";

    const approvals: ToolApprovalResponse[] = pending.map((request) => ({
      type: "tool-approval-response",
      approvalId: request.approvalId,
      approved,
      reason: approved ? "Approved in the CLI" : "Rejected in the CLI",
    }));
    messages.push({ role: "tool", content: approvals });

    result = await generateText({
      model: openai(process.env.OPENAI_MODEL ?? "gpt-5.4"),
      instructions: "If submission was denied, do not request it again.",
      messages,
      tools,
      stopWhen: stepCountIs(5),
    });

    console.log(result.text);
  } finally {
    await stagehand.close();
  }
} finally {
  await browser.close();
}
```

Run it:

```bash
export BROWSERBASE_API_KEY="bb_live_..."
export OPENAI_API_KEY="sk-..."

```

## Why this pattern holds up

`needsApproval` stops the tool before `execute()` runs. The first model call returns a `tool-approval-request`; the second receives a `tool-approval-response` and either performs the click or reports the rejection. Filling and submission are separate tools, so the approval covers one clear side effect.

In an API or queue worker, persist `messages`, the pending approval ID, and the browser session ID before returning control to the reviewer. Reconnect to that Browserbase session when the approval arrives.

## Check your work

- The form fields are filled before the CLI asks for approval.
- Answering `n` never clicks Submit.
- Answering `y` executes the submit tool once and prints the response page URL.
