## User data directory

Persist browser data between sessions.

### Local sessions

For local sessions, point the browser source at a user data directory. Stagehand creates the directory if it does not exist and leaves it in place after the browser shuts down, so the next run starts from the same cookies and local storage:

<View title="TypeScript" icon="js">
```typescript
import { Stagehand } from "@browserbasehq/stagehand";

const stagehand = new Stagehand({
  browser: {
    type: "local",
    userDataDir: "./browser-data",
  },
});

await stagehand.init();
```
</View>

<View title="Python" icon="python">
```python
from stagehand import Stagehand

stagehand = Stagehand(
    browser="local",
    user_data_dir="./browser-data",
)

await stagehand.init()
```
</View>

<View title="Go" icon="golang">
```go
client := stagehand.New(stagehand.StagehandClientInitParams{
	Browser: stagehand.LocalBrowserSource{
		UserDataDir: "./browser-data",
	},
})

if err := client.Init(ctx); err != nil {
	return err
}
```
</View>

<Note>
When no user data directory is set, Stagehand launches Chrome against a temporary profile and deletes it on shutdown, so cookies and local storage do not carry over between runs. `preserveUserDataDir` governs only that generated profile: turn it on to keep the temporary directory after shutdown. A directory you pass as `userDataDir` is kept either way, so the flag is not required for the setup above.
</Note>

{/* TODO: preserveUserDataDir is honored in Python and Go , where the delete only happens for a Stagehand-generated profile. TypeScript ignores the flag: sdk-ts/src/browserSource.ts forwards only userDataDir and port to chrome-launcher, whose destroyTmp always removes a generated profile and never removes one the caller supplied. Explicit userDataDir survives in all three. */}

### Browserbase sessions

For Browserbase sessions, use [contexts](https://docs.browserbase.com/features/contexts) to persist browser data:

<View title="TypeScript" icon="js">
```typescript
import { Stagehand } from "@browserbasehq/stagehand";

const stagehand = new Stagehand({
  apiKey: process.env.BROWSERBASE_API_KEY,
  browser: {
    type: "browserbase",
    browserSettings: {
      context: {
        id: "my-context-id",
        persist: true,
      },
    },
  },
});

await stagehand.init();
console.log("Session ID:", stagehand.browser.browserbaseSessionId);
```
</View>

<View title="Python" icon="python">
```python
import os

from stagehand import BrowserbaseBrowserSettings, Stagehand

stagehand = Stagehand(
    api_key=os.environ["BROWSERBASE_API_KEY"],
    browser="browserbase",
    browser_settings=BrowserbaseBrowserSettings.model_validate({
        "context": {
            "id": "my-context-id",
            "persist": True,
        }
    }),
)

await stagehand.init()
```
</View>

{/* TODO: the Python View fails at init(): sdk-python/src/stagehand/browser_source.py raises NotImplementedError("Browserbase session creation is not implemented yet". TypeScript and Go create sessions normally. */}

<View title="Go" icon="golang">
```go
apiKey := os.Getenv("BROWSERBASE_API_KEY")
persist := true

client := stagehand.New(stagehand.StagehandClientInitParams{
	APIKey: &apiKey,
	Browser: stagehand.BrowserbaseClientBrowserSource{
		BrowserSettings: &stagehand.BrowserbaseBrowserSettings{
			Context: &stagehand.BrowserbaseContext{
				ID:      "my-context-id",
				Persist: &persist,
			},
		},
	},
})

if err := client.Init(ctx); err != nil {
	return err
}
```
</View>

<Warning>
A persisted profile carries cookies, tokens, and site data across runs. Treat the directory or context ID as a credential: keep it out of version control and scope it to a single automation.
</Warning>
