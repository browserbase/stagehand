---
title: "OpenCode"
description: "Give an OpenCode v2 session persistent Stagehand browser tools over MCP/stdio."
---

The OpenCode integration gives an OpenCode 2 agent a persistent Stagehand browser it can drive with `run`, `snapshot`, and `screenshot`. The example uses the [embedded OpenCode SDK](https://opencode.ai/v2/docs/build/sdk/) and connects to the Stagehand facade over MCP/stdio. One facade process owns the browser, so page state and snapshot IDs survive across tool calls.

<Note>
Stagehand ships this experimental integration from the repository rather than publishing it as a standalone adapter.
</Note>

## Prerequisites

- Node.js 24 or newer
- pnpm 11.11.0
- A supported provider API key for the SDK example
- A current Google Chrome installation for local browser mode

The SDK example does not require the OpenCode CLI. Install [OpenCode 2](https://opencode.ai/v2/docs/) separately if you want to use the interactive CLI below.

## Quickstart

<Steps>
  <Step title="Clone and build Stagehand">
```bash
git clone https://github.com/browserbase/stagehand.git
cd stagehand
pnpm install --frozen-lockfile
pnpm exec turbo run build \
  --filter @browserbasehq/stagehand-integrations-opencode-sdk
```
  </Step>
  <Step title="Configure the OpenCode agent">
The SDK example uses provider credentials from the environment:

```bash
export ANTHROPIC_API_KEY="your-anthropic-api-key"
```

Set `OPENCODE_MODEL` to a `provider/model` value only when you want to override OpenCode's default.

The example uses a private HOME and config directory, so it does not reuse credentials saved by an OpenCode CLI login. Export the provider API key in the shell that runs the example.
  </Step>
  <Step title="Choose the browser">
The example defaults to Browserbase when `BROWSERBASE_API_KEY` is set, otherwise it uses local Chrome:

```bash
export STAGEHAND_BROWSER="browserbase"
export BROWSERBASE_API_KEY="your-browserbase-api-key"
```
  </Step>
  <Step title="Run a browser task">
```bash
pnpm --dir packages/integrations/opencode start -- \
  "Open https://example.com, snapshot it, request a screenshot, and report the page title."
```
  </Step>
</Steps>

## Configuration

| Variable | Purpose |
| --- | --- |
| `OPENCODE_MODEL` | Optional OpenCode model in `provider/model` form. |
| Provider variables | Credentials supported by OpenCode, such as `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`. The SDK example does not forward them to the MCP child. |
| `STAGEHAND_BROWSER` | Select `local` or `browserbase`. Defaults to Browserbase when `BROWSERBASE_API_KEY` is set, otherwise local. |
| `BROWSERBASE_API_KEY` | Required for Browserbase. |
| `BROWSERBASE_PROJECT_ID` | Optional Browserbase project ID. |
| `STAGEHAND_MODEL_NAME` | Optional model for Stagehand AI methods called inside `run`. |
| `STAGEHAND_MODEL_API_KEY` | Required with `STAGEHAND_MODEL_NAME`. |

## Keep the browser session alive

The example creates an isolated temporary workspace and config directory, then creates one SDK host and one session for the task. The Stagehand facade stays alive for the full model loop. Preserve that lifetime if you adapt the integration; a new facade process per tool call starts a new browser. MCP image results remain in OpenCode's tool loop, so `screenshot` stays multimodal.

OpenCode 2's `sessions.prompt()` admits the prompt before the model finishes. The adapter calls `sessions.wait()`, checks the session outcome, and reads every page of the message timeline before returning the final assistant text. It removes the session and closes the host after the run, then deletes the temporary workspace.

The embedded host opens no HTTP listener. Its config supplies one direct `stagehand` MCP server and denies all other tools. A wrapper forwards only non-empty `STAGEHAND_*` and `BROWSERBASE_*` variables plus the process values required to launch Node. Provider credentials remain in the OpenCode host.

## Connect a running OpenCode CLI

The package ships a project-scoped v2 `opencode.json` that mounts the Stagehand facade as a direct MCP server and allows only its three tools. The command path is relative to the package, so start the CLI from that directory:

```bash
cd packages/integrations/opencode
opencode mcp list
opencode --standalone
```

`--standalone` starts a private server with the current shell's exports. OpenCode 2 otherwise uses a shared background service that may have started before you exported the browser credentials. See [OpenCode's background service guide](https://opencode.ai/v2/docs/cli/#background-service).

The config uses `mcp.servers` and sets `codemode: false` so the three facade tools appear directly in the model's tool list. Its ordered `permissions` rules deny every action, then allow `stagehand_run`, `stagehand_snapshot`, and `stagehand_screenshot`. See the [MCP configuration](https://opencode.ai/v2/docs/mcp-servers) and [permission rules](https://opencode.ai/v2/docs/permissions).

OpenCode passes the server's environment to local MCP processes, including exported provider credentials. The CLI config does not use the SDK example's environment wrapper. If JavaScript passed to `run` uses `act`, `extract`, or `observe`, export `STAGEHAND_MODEL_NAME` and the separate `STAGEHAND_MODEL_API_KEY`; OpenCode's provider credential is not reused as the Stagehand credential. For a headless one-shot run:

```bash
opencode run --standalone "your instruction"
```

<Warning>
`run` executes model-authored JavaScript in the browser. Use Browserbase for untrusted tasks and review the [CLI agent security boundary](/v4/integrations/cli-agents/overview#security-boundary).
</Warning>
