---
title: "OpenCode"
description: "Give an OpenCode v2 session persistent Stagehand browser tools over MCP/stdio."
---

The OpenCode integration uses `@opencode/sdk` and mounts the Stagehand facade as one MCP/stdio server. One OpenCode session and one facade process own the browser across `run`, `snapshot`, and `screenshot` calls.

<Note>
Stagehand ships this experimental integration from the repository rather than publishing it as a standalone adapter.
</Note>

## Prerequisites

- Node.js 24 or newer
- pnpm 11.10.0
- An OpenCode provider login or supported provider API key
- A current Google Chrome installation for local browser mode

## Quickstart

<Steps>
  <Step title="Clone and build Stagehand">
```bash
git clone https://github.com/browserbase/stagehand.git
cd stagehand
pnpm install --frozen-lockfile
pnpm exec turbo run build \
  --filter @browserbasehq/stagehand-integrations-opencode-sdk
```
  </Step>
  <Step title="Authenticate OpenCode">
The SDK example uses provider credentials from the environment:

```bash
export ANTHROPIC_API_KEY="your-anthropic-api-key"
```

Set `OPENCODE_MODEL` to a `provider/model` value only when you want to override OpenCode's default.
  </Step>
  <Step title="Choose the browser">
The example defaults to Browserbase when `BROWSERBASE_API_KEY` is set, otherwise it uses local Chrome:

```bash
export STAGEHAND_BROWSER="browserbase"
export BROWSERBASE_API_KEY="your-browserbase-api-key"
```
  </Step>
  <Step title="Run a browser task">
```bash
pnpm --dir packages/integrations/opencode start -- \
  "Open https://example.com, snapshot it, request a screenshot, and report the page title."
```
  </Step>
</Steps>

## Configuration

| Variable | Purpose |
| --- | --- |
| `OPENCODE_MODEL` | Optional OpenCode model in `provider/model` form. |
| Provider variables | Credentials supported by OpenCode, such as `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`. The SDK example does not forward them to the MCP child. |
| `STAGEHAND_BROWSER` | Select `local` or `browserbase`. Defaults to Browserbase when `BROWSERBASE_API_KEY` is set, otherwise local. |
| `BROWSERBASE_API_KEY` | Required for Browserbase. |
| `BROWSERBASE_PROJECT_ID` | Optional Browserbase project ID. |
| `STAGEHAND_MODEL_NAME` | Optional model for Stagehand AI methods called inside `run`. |
| `STAGEHAND_MODEL_API_KEY` | Required with `STAGEHAND_MODEL_NAME`. |

## SDK and session lifecycle

The example creates an isolated temporary workspace and config directory so the host does not pick up ambient OpenCode settings. It creates one session, sends one prompt, waits for completion, reads the full message timeline, deletes the session, and closes the host. The Stagehand facade MCP server stays alive for the full prompt, preserving page state and snapshot IDs. MCP image blocks remain in OpenCode's tool loop, so `screenshot` stays multimodal.

The embedded host's config supplies one direct `stagehand` MCP server and denies permission to all other tools. The MCP server launches through a wrapper that forwards only the Stagehand and Browserbase variables selected for the browser process.

The facade child receives only non-empty `STAGEHAND_*` and `BROWSERBASE_*` variables, plus basic process variables needed to start it. Provider credentials remain in the OpenCode host.

## Connect a running OpenCode CLI

The package ships a project-scoped v2 `opencode.json` that mounts the Stagehand facade as a direct MCP server and allows only its three tools. The command path is relative to the package, so start the CLI from that directory:

```bash
cd packages/integrations/opencode
opencode mcp list
opencode
```

OpenCode passes the CLI's shell environment to local MCP servers, so the facade process also receives provider credentials that you export in that shell. This differs from the SDK example's explicit environment allowlist. If JavaScript passed to `run` uses `act`, `extract`, or `observe`, export `STAGEHAND_MODEL_NAME` and the separate `STAGEHAND_MODEL_API_KEY`; OpenCode's provider credential is not reused as the Stagehand credential. The exports above are otherwise the only configuration. For a headless one-shot run:

```bash
opencode run "your instruction"
```

<Warning>
`run` executes model-authored JavaScript in the browser. Use Browserbase for untrusted tasks and review the [CLI agent security boundary](/v4/integrations/cli-agents/overview#security-boundary).
</Warning>
