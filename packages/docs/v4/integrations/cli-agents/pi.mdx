---
title: "Pi"
description: "Give the Pi coding agent persistent Stagehand browser tools over MCP/stdio."
---

The Pi integration mounts Stagehand's `run`, `snapshot`, and `screenshot` tools through Pi's built-in MCP support. One MCP server process owns the browser, so navigation, authentication, and page state survive across tool calls.

<Note>
Stagehand ships this experimental integration from the repository rather than publishing it as a standalone adapter. The example is verified against Pi 1.4.0.
</Note>

## Prerequisites

- Node.js 24 or newer
- pnpm 11.11.0
- A model-provider credential for Pi, such as `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`
- Google Chrome for local browser mode

## Quickstart

<Steps>
  <Step title="Clone and build Stagehand">
```bash
git clone https://github.com/browserbase/stagehand.git
cd stagehand
pnpm install --frozen-lockfile
pnpm exec turbo run build \
  --filter @browserbasehq/stagehand-integrations
```
  </Step>
  <Step title="Configure Pi's model">
```bash
export OPENAI_API_KEY="your-openai-api-key"
```

Use `ANTHROPIC_API_KEY` instead for an Anthropic model. This credential is for Pi's model.
  </Step>
  <Step title="Choose the browser">
The MCP server uses Browserbase when `BROWSERBASE_API_KEY` is set; otherwise it uses local Chrome. To select Browserbase explicitly:

```bash
export STAGEHAND_BROWSER="browserbase"
export BROWSERBASE_API_KEY="your-browserbase-api-key"
```
  </Step>
  <Step title="Run a browser task">
```bash
cd packages/integrations/pi
pnpm start "Open https://example.com and report the page title." </dev/null
```

The start script runs `pi --approve --no-session -p`. Start from this directory so Pi finds `.pi/mcp.json` and resolves its relative server path.
  </Step>
</Steps>

<Note>
Print mode reads piped stdin, so redirect `</dev/null` when supplying the prompt as an argument. `--approve` trusts project-local files for this process so the project MCP configuration loads without an interactive trust prompt.
</Note>

## Connect a Pi CLI

The project `.pi/mcp.json` mounts the shared facade server:

```json
{
  "mcpServers": {
    "stagehand": {
      "command": "node",
      "args": ["../core/dist/facade/stdio-server.mjs"],
      "exposure": "direct",
      "description": "Persistent Stagehand browser tools"
    }
  }
}
```

Run `pi --approve` from `packages/integrations/pi` for an interactive session. Direct exposure declares `mcp__stagehand__run`, `mcp__stagehand__snapshot`, and `mcp__stagehand__screenshot` to the model. Pi otherwise defaults MCP servers to `codemode` exposure, where tools are reached through scripts.

To register the server for other projects, use an absolute path:

```bash
pi mcp add stagehand --exposure direct --description "Persistent Stagehand browser tools" -- \
  node /absolute/path/to/stagehand/packages/integrations/core/dist/facade/stdio-server.mjs
```

If you previously installed the native Stagehand Pi extension, remove that installation before enabling the MCP mount to avoid duplicate browser tools. The extension's `pi install` setup is no longer used.

## Configuration

| Variable | Purpose |
| --- | --- |
| `OPENAI_API_KEY` | Credential for Pi's model. |
| `ANTHROPIC_API_KEY` | Alternative credential for Pi's model. |
| `STAGEHAND_BROWSER` | Select `local` or `browserbase`. |
| `BROWSERBASE_API_KEY` | Required for Browserbase. |
| `BROWSERBASE_PROJECT_ID` | Optional Browserbase project ID. |
| `STAGEHAND_MODEL_NAME` | Optional. The facade tools are deterministic and do not call a Stagehand model. |
| `STAGEHAND_MODEL_API_KEY` | Optional credential for `STAGEHAND_MODEL_NAME`; the MCP child can infer supported provider keys from its environment. |

## Session lifecycle

Keep one MCP connection open for the task. Navigation, authentication, and page state persist across browser calls. Closing the session disconnects the MCP child and closes its browser. Starting a server per call loses the previous browser's state.

The MCP child inherits the parent process environment, including Pi's model credentials. The deterministic browser tools do not need those model credentials.

<Warning>
`run` executes model-authored JavaScript in the browser. Use Browserbase for untrusted tasks and review the [integration security boundary](/v4/integrations/cli-agents/overview#security-boundary).
</Warning>
