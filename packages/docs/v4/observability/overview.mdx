Configure `telemetry.traces` in `Stagehand.create()` to export traces from the browser extension. Stagehand sends OTLP over HTTP using JSON to the full traces URL, including `/v1/traces`. You do not need a provider SDK in your application.

Use an [OpenTelemetry Collector](/v4/observability/otel-collector) to forward traces to multiple backends or convert JSON to protobuf.

## Trace format

Stagehand samples all spans and sets these resource attributes:

| Attribute | Value |
| --- | --- |
| `service.name` | `stagehand-service-worker` |
| `service.namespace` | `browserbase` |
| `service.version` | The browser extension version |
| `stagehand.client.name` | The connected SDK's name |
| `stagehand.client.version` | The connected SDK's version |

Operation spans wrap calls such as `act`, `observe`, and `extract`. They set `stagehand.span.type` to `operation` and store their structured payload as JSON in `stagehand.span.data`. Failures set error status and record an exception event.

Each log record produces a separate span with `stagehand.span.type = log`. Its attributes include `stagehand.log.level`, `stagehand.log.message`, and a JSON payload in `stagehand.log.data`. Logs inside an operation use that operation as their parent. The logging level filters SDK log notifications, not exported log spans.

These are Stagehand attributes. Provider-specific LLM inputs, outputs, token usage, costs, and session grouping are not automatically populated.

## Export lifecycle

The exporter batches spans every second. Close Stagehand before closing the browser so pending spans can flush. Export failures do not fail cleanup; verify receipt in the provider's UI.

For Browserbase sessions, the endpoint must be reachable from the remote browser. `localhost` refers to that browser, not the machine running your SDK. For full configuration details, see [Tracing](/v4/configuration/observability#tracing).
