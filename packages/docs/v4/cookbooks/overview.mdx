Cookbooks are runnable browser jobs with a source folder, an agent prompt, defined output, and failure checks. Start with the job you need, then adapt its target and validation.

| Resource | What it contains |
| --- | --- |
| Cookbooks | Projects you can clone, run, and adapt, including checkpoints and authenticated sessions |
| [Best practices](/v4/best-practices/caching) | Small patterns for caching and browser data |
| [Showcase](https://stagehand.dev/showcase) | Recorded jobs on real sites, with benchmark results |
| [Functions](/v4/best-practices/deployments) | Deployment instructions and CLI templates |

Cloud recipes print a Browserbase session link and limit browser lifetime to five minutes. Model calls and integrations can add charges. Page and step limits bound work, not a fixed dollar amount. See [model configuration](/v4/configuration/models).

| Cookbook | Use it when | Inputs | Output | Stagehand methods | Languages |

| [Reuse an authenticated session](/v4/cookbooks/persisted-login) | A recurring job needs persisted login | Optional context ID, test credentials | Authentication and reuse receipt | `act()`, browser context | TypeScript, Python |
| [Export a paginated book catalog](/v4/cookbooks/paginated-catalog) | The number of result pages is unknown | Catalog URL, page limit | Validated `out/catalog.json` | `extract()`, `observe()`, `act()` | TypeScript, Python |

## Run a cookbook

Choose a cookbook in [`packages/examples/cookbooks`](https://github.com/browserbase/stagehand/tree/main/packages/examples/cookbooks), then clone the repository:

```bash
git clone --depth 1 https://github.com/browserbase/stagehand.git
cd stagehand
```

For TypeScript, use Node.js 22.18+, pnpm, and [just](https://just.systems/). Run `pnpm install --frozen-lockfile` once from the repository root. Copy the selected cookbook's `typescript/.env.example` to `typescript/.env`, fill in its keys, then run `just cookbook <slug>` from the root. Replace `<slug>` with the cookbook's folder name, such as `paginated-catalog`. The command builds the local SDK and extension and starts the recipe in its TypeScript directory, where `.env` and `out/` live. All TypeScript cookbooks share the root workspace and lockfile.

For Python, use Python 3.11+ and uv, plus Node.js 22.18+, pnpm, and just to build the extension. Run `just install` once from the repository root. Copy the selected cookbook's `python/.env.example` to `python/.env`, fill in its keys, then run `just cookbook-python <slug>` from the root. The command builds the extension and starts the recipe in its Python directory, where `.env` and `out/` live. Python cookbooks use the local SDK source and share the root `uv.lock` and `.venv`; each keeps its own `pyproject.toml`.

Open the cookbook's README or docs page for required keys, inputs, and output checks.

For recorded data-collection and QA jobs, see the [showcase](https://stagehand.dev/showcase).

For individual SDK methods, start with the [Stagehand basics](/v4/basics/act).
