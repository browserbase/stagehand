Cookbooks are runnable browser jobs with a source folder, an agent prompt, defined output, and failure checks. Start with the job you need, then adapt its target and validation.

| Resource | What it contains |
| --- | --- |
| Cookbooks | Projects you can clone, run, and adapt, including checkpoints and authenticated sessions |
| [Best practices](/v4/best-practices/caching) | Small patterns for caching and browser data |
| [Showcase](https://stagehand.dev/showcase) | Recorded jobs on real sites, with benchmark results |
| [Functions](/v4/best-practices/deployments) | Deployment instructions and CLI templates |

Cloud recipes print a Browserbase session link and limit browser lifetime to five minutes, or 30 minutes for durable agents. Model calls and integrations can add charges. Page and step limits bound work, not a fixed dollar amount. See [model configuration](/v4/configuration/models).

| Cookbook | Use it when | Inputs | Output | Stagehand methods | Languages |
| --- | --- | --- | --- | --- | --- |
| [Reuse an authenticated session](/v4/cookbooks/persisted-login) | A recurring job needs persisted login | Optional context ID, test credentials | Authentication and reuse receipt | `act()`, browser context | TypeScript, Python, Go |
| [Export a paginated book catalog](/v4/cookbooks/paginated-catalog) | The number of result pages is unknown | Catalog URL, page limit | Validated `out/catalog.json` | `extract()`, `observe()`, `act()` | TypeScript, Python, Go |
| [Save extracted files to a bucket](/v4/cookbooks/files-to-bucket) | Extracted page data and downloaded bytes must reach object storage | Target page, optional S3 bucket | Local JSON and cover, optional bucket objects | `extract()` | TypeScript |
| [Approve a form submission](/v4/cookbooks/approve-form-submission) | A browser action needs human consent | Test form values, approval answer | Submitted URL or a clear rejection | `act()` | TypeScript, Python, Go |

## Durable agents

Use these when browser work must wait for a human, preserve completed results, or reconcile an action after a crash. Each is an independent TypeScript CLI project. The agent's state survives process exit; browser sessions and verification codes still expire.

| Cookbook | Framework | Durable behavior |
| --- | --- | --- |
| [Approve an order later](/v4/cookbooks/pi-durable-approval) | Pi Durable on durable-harness | Save the exact proposal and verify the human's submission |
| [Collect merchant receipts](/v4/cookbooks/libfx-receipts) | Native libfx | Reuse completed reads and continue incomplete portals |
| [Recover an interrupted submission](/v4/cookbooks/opencode-submission) | OpenCode on durable-harness | Verify confirmation without repeating the submission |

The harness recipes use the explicitly pinned beta `durable-harness@0.0.1-beta.6`. Follow each README for inputs, model keys, recovery limits and cleanup.

## Durable storage and hosting

These are local CLI examples with offline validation. Browserbase flows and paid model turns still need live verification. Start with the approval recipe for a persisted human decision, use receipts for collection recovery, and compare the interrupted-submission recipe to see why a saved approval does not establish an action's outcome.

Pi Durable is an agent framework with its own conversation, task and document model. `durable-harness/pi-durable` supplies World-backed storage for it. Native libfx already has durability; it does not need a durable-harness adapter. The OpenCode recipe uses that adapter package to persist its execution. See [Earendil's introduction](https://earendil.com/posts/pi-durable/) and [Vercel's overview](https://vercel.com/blog/making-every-harness-durable/).

| Combination | Included here |
| --- | --- |
| Pi Durable with a local Workflow World | Approval CLI |
| Native libfx local durability | Receipt CLI, plus its separate on-disk manifest |
| OpenCode with a local Workflow World | Submission CLI |
| Vercel or a self-hosted Postgres World | Requires deployment and queue setup |
| Turso or another Workflow World | Not implemented or verified in these recipes |

All three resume when you invoke the CLI. A deployed durable agent also needs a host or worker to drive interrupted turns. Changing storage does not keep that worker running or extend the Browserbase session. These CLIs explicitly construct local backends, so setting World environment variables alone does not migrate them. See [self-hosting](https://vercel.com/docs/agent-harnesses/self-hosting) for host and queue setup.

## Durable dependency versions

Checked against npm release tags on October 22, 2026. New framework dependencies use the latest supported release; shared utilities follow the existing cookbook ranges and frozen lockfiles.

| Package | Cookbook version | Reason |
| --- | --- | --- |
| Pi Durable, pi-ai and Chord | `1.4.0` | Latest published release |
| libfx | `0.0.14` | Latest release; excludes development builds |
| durable-harness | `0.0.1-beta.6` | Latest published beta |
| Workflow local World | `5.1.2` | Latest release |
| OpenCode client, core, schema and server | `2.0.22` | Exact versions required by the current harness adapter |
| Effect | `4.0.0-rc.112` | Exact version required by that adapter and OpenCode |

OpenCode `2.1.3` and Effect `4.0.5` are newer standalone releases. The current durable-harness adapter checks its required versions at runtime, so upgrading them alone prevents the agent from running. Revisit those pins when a compatible adapter is published.

Zod stays at the repository's `4.4.3` pin. TypeScript, Node types, tsx, dotenv and Browserbase SDK use the same ranges as the existing repository setup. These examples do not upgrade shared tooling independently. A version check is not live validation: manually verify each of the three browser flows before a PR.

## Run a cookbook

Choose a cookbook folder in [`packages/examples/cookbooks`](https://github.com/browserbase/stagehand/tree/main/packages/examples/cookbooks), then check out that folder:

```bash
git clone --depth 1 --sparse https://github.com/browserbase/stagehand.git
cd stagehand
git sparse-checkout set packages/examples/cookbooks/<cookbook-name>
```

Open the cookbook's README or docs page for its supported languages, required keys, install steps, and run command. Each cookbook folder contains its own source and configuration.

For recorded data-collection and QA jobs, see the [showcase](https://stagehand.dev/showcase).

For individual SDK methods, start with the [Stagehand basics](/v4/basics/act).
