## When to use this

Use this when an agent collects data from several authenticated pages and must preserve completed work across restarts. libfx runs the durable conversation; Stagehand extracts visible receipt metadata. Human login happens in Browserbase Live View.

| Browser | Language | Output |
| --- | --- | --- |
| Browserbase | TypeScript | Receipt metadata in `receipts.json`, with source completeness |

## Goal and output

Read one to five merchant receipt-list URLs. Save each completed source before returning its tool result. If a page needs login, persist a handoff and exit. After human return or a crash, continue incomplete sources and reuse saved records.

The output covers up to 50 visible records per source. It does not paginate or download PDFs. An empty page remains incomplete because the schema cannot distinguish an empty account from blocked access.

## Prerequisites and inputs

Use Node.js 24.18+ and pnpm. Add `BROWSERBASE_API_KEY`, `OPENAI_API_KEY` and `AI_GATEWAY_API_KEY` to `.env`. OpenAI powers Stagehand extraction; AI Gateway powers libfx. Set `RECEIPT_URLS` to a JSON array of one to five HTTPS merchant receipt-list URLs you intend the agent to access.

The recipe pins `libfx@0.0.14`. Shared utilities follow the existing cookbook versions. See the [version notes](/v4/cookbooks/overview#durable-dependency-versions).

## Check out and run

Source: [`packages/examples/cookbooks/libfx-receipts`](https://github.com/browserbase/stagehand/tree/main/packages/examples/cookbooks/libfx-receipts). Use the [sparse checkout instructions](/v4/cookbooks/overview#run-a-cookbook), then:

```bash
cd packages/examples/cookbooks/libfx-receipts/typescript
cp .env.example .env
pnpm install --frozen-lockfile
# Fill in .env, including RECEIPT_URLS, before starting.
pnpm start
```

If a handoff appears, complete login in the printed Live View, then:

```bash
pnpm start return <decision-id>
pnpm start status
pnpm start cleanup
```

Use `pnpm start resume` after an interruption, with the same state directory and source URLs.

## How the job works

### Give libfx a durable local backend

`src/index.ts` configures the library's own persistence. It does not invoke the fx CLI or install a durable-harness adapter:

```typescript
const agent = createFxAgent({
  name: "receipt-collector",
  model: process.env.AGENT_MODEL ?? "openai/gpt-6-luna",
  durability: local({ dir: join(directory, "fx") }),
  tools,
  instructions,
});
```

libfx stores the conversation and tool outcomes. The recipe's `FileStore` separately stores source results, browser identity and handoff state in `manifest.json`. Keep the whole directory together.

### Save a source before returning its result

The serialized `read_receipts` tool checks the manifest before navigation. Its core recovery pattern is:

```typescript
const saved = before.receipts.find((entry) => entry.url === url);
if (saved) return saved;

const records = await browser.receipts(url);
// The runnable tool rejects empty results before this write.
await store.update((draft) => {
  draft.receipts.push({ url, records });
});
return { url, records };
```

If the process dies after that write, libfx may need to repeat the unfinished tool. The tool returns saved records instead of extracting the page again. Source validation, ownership and call-budget checks surround this excerpt in the runnable code.

### Deliver each input with a stable identity

Initial and human-return inputs have stable message IDs. Retrying delivery covers a crash before libfx accepted the input, while deduplicating one it already accepted:

```typescript
const turn = session.prompt(text, {
  messageId: returned ? `return-${state.decision!.id}` : "initial",
});
```

After 20 extraction attempts, the next incomplete read saves a handoff. Human return grants another 20 attempts without deleting completed sources.

## Expected result and manual checks

`STATE_DIR` defaults to `out/run`. It contains the libfx journal, `run.json`, `manifest.json` and `receipts.json`. `complete: true` means every configured URL has saved records, not that every receipt in the account was collected.

Before a PR, configure two sources and run the crash check:

```bash
CRASH_AFTER_RECEIPT=1 pnpm start
# After the intentional SIGKILL, wait 30 seconds for the lock to expire.
pnpm start resume
pnpm start status
pnpm start cleanup
```

The inline flag applies only to the first command. Remove any `CRASH_AFTER_RECEIPT=1` setting from `.env` before resuming. Verify that the first source reuses its saved records and the second completes. Separately test a login handoff: the pending decision must survive process exit and collection must continue after return.

Run `pnpm typecheck` and `pnpm test` for offline checks. Tests cover libfx message deduplication, manifest reopen, handoff ownership and the read budget. Live extraction and paid model execution still need your verification.

## Session lifetime and recovery

The browser is a 30-minute keep-alive session, including human waiting time. A persisted handoff does not extend the browser or its login. Reconnect failure stops collection. Retain prior output when starting a fresh task, and never claim missing sources completed.

Run one CLI process per state directory. After a hard crash, the lock expires after 30 seconds. Keep the same source URLs and dependency pins when resuming. `cleanup` releases the browser and retains records. A crash before saving a newly allocated session ID can leave a browser until its timeout.

This CLI resumes when invoked; changing libfx's backend alone does not migrate the separate manifest. See [storage and hosting](/v4/cookbooks/overview#durable-storage-and-hosting) before deploying it.
